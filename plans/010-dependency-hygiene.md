## Why this matters

Three independent hygiene items, all small:

1. The `geist` npm package is used ONLY for four .woff2 font files referenced
   from CSS — but it declares a peer dependency on `next >=13.2.0`, which pnpm
   auto-installs. The app therefore carries the entire Next.js 16 tree as a
   transitive dependency of a font, and that tree contains the
   **postcss < 8.5.10 moderate vulnerability** (GHSA-qx2v-qp2m-jg93) reported
   by `pnpm audit`. Vendoring the font files removes Next.js, postcss, and the
   audit finding in one move.
2. The second moderate audit finding is **brace-expansion >=5.0.0 <5.0.6**
   (GHSA-jxxr-4gwj-5jf2) via `electron-builder > app-builder-lib > minimatch`.
   A pnpm override to >=5.0.6 clears it (same mechanism as the existing `tmp`
   override).
3. `packages/db` pins `better-sqlite3 ^11.10.0` while `apps/desktop` pins
   `^12.10.0` — two native module majors in one workspace. The desktop app
   already runs the db package's code against v12 at runtime (workspace alias
   resolves `@applyocalypse/db` source, but the rebuilt native binary is v12),
   so aligning `packages/db` to ^12 matches reality and removes drift.

## Steps

### Step 1: Vendor the font files

1. Create `apps/desktop/src/renderer/assets/fonts/`.
2. Copy from `apps/desktop/node_modules/geist/dist/fonts/`:
   - `geist-sans/Geist-Variable.woff2`
   - `geist-sans/Geist-Italic[wght].woff2`
   - `geist-mono/GeistMono-Variable.woff2`
   - `geist-mono/GeistMono-Italic[wght].woff2`
   into the new directory (flatten — keep the file names).
3. Copy the license: find `LICENSE*` or `OFL*` under
   `apps/desktop/node_modules/geist/` and place it as
   `apps/desktop/src/renderer/assets/fonts/LICENSE-geist.txt`. If no license
   file ships in the package, create the file containing the line
   "Geist fonts (c) Vercel — SIL Open Font License 1.1" and the npm package
   URL.
4. Rewrite the four `url()` values in `fonts.css` to
   `./assets/fonts/<filename>` (relative to fonts.css's own location —
   confirm fonts.css sits at `apps/desktop/src/renderer/fonts.css` and adjust
   the relative segment accordingly).

**Verify**: `pnpm --filter @applyocalypse/desktop build` → exit 0; then
`grep -c "node_modules/geist" apps/desktop/src/renderer/fonts.css` → 0.

### Step 2: Remove the geist dependency

Delete the `"geist": "^1.3.0"` line from `apps/desktop/package.json`, then
`pnpm install`.

**Verify**: `pnpm audit --audit-level moderate` → the postcss finding is gone.
`pnpm --filter @applyocalypse/desktop build` → exit 0.

### Step 3: Override brace-expansion

In root `package.json`, extend the existing overrides block:

```json
"overrides": {
  "tmp": ">=0.2.6",
  "brace-expansion@>=5.0.0 <5.0.6": ">=5.0.6"
}
```

Then `pnpm install`.

**Verify**: `pnpm audit --audit-level moderate` → "No known vulnerabilities
found" (zero findings at moderate level).

### Step 4: Align better-sqlite3

In `packages/db/package.json`, change `"better-sqlite3": "^11.10.0"` to
`"^12.10.0"`. Then `pnpm install`.

**Verify**: `pnpm test` → all pass (db repository tests run against v12);
`pnpm typecheck` → exit 0.

### Step 5: Confirm packaged font loading

The renderer build inlines or emits the woff2 assets via Vite. Check the build
output: `ls apps/desktop/out/renderer/assets/ | grep -i geist` (or however the
hashed names appear) — at least the variable fonts must be emitted, OR the CSS
in `out/renderer/assets/*.css` references data-URIs. Either is fine; what must
NOT remain is a `node_modules/geist` path in the built CSS:
`grep -rn "node_modules/geist" apps/desktop/out/renderer/` → no matches.

**Verify**: command above → no matches.
